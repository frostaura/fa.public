# Gotchas

- **The backend gate is real but invisible in `ci.yml`.** The general trap is the division's ([`../../../memory/gotchas.md`](../../../memory/gotchas.md)); here, the only direct .NET step is `dotnet restore` — `npm run lint` / `build` / `test` fan out to `dotnet format --verify-no-changes`, `dotnet build src/backend/FrostAura.slnx` and `dotnet test`. A skim concludes the backend is absent; it is hidden.
- **Any push to `main` republishes the images.** CI runs on every push and the image workflow fires on its success, with no path filter — the 2026-09-16 context-only pushes each rebuilt and re-pointed `:latest` on Docker Hub (`gh run list`, 2026-11-20). The site is live off what is probably that `:latest` (see state); if its host tracks `:latest`, a memory edit is already a release.
- **The image's default database path is outside its own volume.** `appsettings.json` ships `Data Source=frostaura.db`; with `WORKDIR /app` that is `/app/frostaura.db`, while the Dockerfile declares `VOLUME ["/app/data"]`. Only the `.env` override (`ConnectionStrings__DefaultConnection` under `/app/data/`, checked by pattern 2026-11-20) puts the data on the volume. A host that runs the image without that key persists submissions in the container layer and loses them on recreate.
- **Unconfigured SMTP fails silently.** `SubmissionNotificationService` skips both sends when `IsConfigured` is false; the submission still persists, with status `Received` instead of `Processed`, and the API still returns a receipt. The visitor sees success and nobody is notified — the two-email contract breaks without an error.
- **`/health` through the web host is the SPA, not the API.** nginx proxies only `/api/`, so `frostaura.net/health` returns 200 with `index.html` (probed 2026-11-20) even if the API is down. Probe API liveness through a submissions route instead: a 405 on `GET` comes from the API, a 502 means it is gone.
- **`.dockerignore` exists only on this disk.** `.gitignore` ignores it (re-verified 2026-11-20), so CI and every fresh clone build with none, and `src/backend/Dockerfile` runs `COPY . .` into the SDK stage. The disk copy excludes `.env` and `*.db`; a fresh clone holding a real `.env` or a populated dev database sends both into the build stage (not the final image).
- **"`/docs` is the source of truth" is written twice** — `docs/architecture/system-components.md:10` and the repo-layout block in `README.md`. With the architecture docs untouched since the scaffold, neither is true; treat the code as the source, and correct both files in one pass or the claim survives in the other.
- **The local dev database holds test fixtures only.** `src/backend/FrostAura.Api/frostaura.development.db` is untracked (`.gitignore` `**/*.db*`); re-inspected on a scratch copy 2026-11-20, both submission tables hold only `example.com` rows. Not a PII store today — but it is where real data would land if the API were pointed at it, so never commit it. The untracked `.env` is a byte-identical copy of `.env.example` written by `make ensure-env` (`cmp`, 2026-11-20), and holds no secret.
- **Three empty untracked directories read as a second asset location** — `src/web/assets/brand/`, `src/web/careers/`, `src/web/investors/`. The real artwork is `src/web/src/assets/brand/`; an asset dropped in the wrong one fails silently at build.
- **Do not copy a frontend config in from a sibling repo unchecked** — this one's Vite major and test DOM differ; the cross-repo comparison is the division's ([`../../../memory/frontend-fracture.md`](../../../memory/frontend-fracture.md)).
