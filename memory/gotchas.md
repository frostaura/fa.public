# Gotchas

- **The backend gate is real but invisible in the workflow file.** The generalised trap belongs to the division ([`../../../memory/gotchas.md`](../../../memory/gotchas.md)); concretely here, `ci.yml` contains no `dotnet build` and no `dotnet test` step — it calls `npm run lint` / `build` / `test`, and those scripts fan out to `dotnet format --verify-no-changes`, `dotnet build src/backend/FrostAura.slnx` and `dotnet test`. The one direct .NET step in the file is `dotnet restore`, which is why a reader skimming it concludes the backend is absent rather than hidden. `FrostAura.Tests` reaches the submission endpoints and the email-settings binding and nothing else. Thin, but not vacuous.
- **There is no Portainer redeploy step.** `docker-build-push.yml` stops at the Docker Hub push; no workflow here mentions Portainer. The standard FrostAura deploy chain is incomplete on this repo and an agent will reasonably assume otherwise.
- **Losing the `frostaura-data` volume loses every careers and investor submission**, and there is no migration path onto it either. That hazard, the SQLite deviation behind it and the schema-evolution gap are open questions: [`questions.md`](questions.md).
- Vite is on **8.x** here and tests use `happy-dom` rather than `jsdom`. The division holds the cross-repo comparison ([`../../../memory/frontend-fracture.md`](../../../memory/frontend-fracture.md)); locally, the point is simply this: do not copy a frontend config in from a sibling without checking it.
- **"`/docs` is the source of truth" is written in two places, and fixing one leaves the other.** `docs/architecture/system-components.md:10` says it, and `README.md`'s repo-layout block says it again ("Source-of-truth docs for the public-site system"). With the three architecture files untouched since the 2026-04-06 scaffold, neither is true — treat the code as the source, and when you correct the doc, correct the README in the same pass or the claim simply survives in the other home. Re-verified 2026-09-16.
- **An untracked local database sits in the API project.** `src/backend/FrostAura.Api/frostaura.development.db` exists on disk and is ignored by `.gitignore` (`**/*.db*`). It is the local counterpart of the PII question — it may hold real submissions entered while testing, it is backed up nowhere, and nothing but this line records it. Do not commit it; do not assume it is empty.
- **Three untracked empty directories read as a second asset location** — `src/web/assets/brand/`, `src/web/careers/`, `src/web/investors/` hold no files at all. The real vendored artwork is `src/web/src/assets/brand/`. Adding an asset to the wrong one fails silently at build time.
- **The vendored Gaia tree is gone from this repo and must not come back**, and nothing had ever wired any of it (no `.mcp.json`, no CI reference). Here the removal is **committed and pushed**, so this repo carries no pending change set. Procedure is meant to come from the Gaia plugins, whose installed-versus-authored state is root's to state ([`../../../../memory/plugin-roster-drift.md`](../../../../memory/plugin-roster-drift.md)); the evidence behind the rule is [`../../../memory/vendored-skills-verdict.md`](../../../memory/vendored-skills-verdict.md). **Do not read a missing skill as the cause of the stack deviations** — those predate the vendored set and survived it; they are a stack decision, not a tooling gap.
