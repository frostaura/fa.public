# Open questions

- **SQLite instead of PostgreSQL, holding PII, with no backup.** Re-verified 2026-09-16: `Microsoft.EntityFrameworkCore.Sqlite` 10.0.5 in `FrostAura.Infrastructure` and in the test project, and no Npgsql reference anywhere in the repo. `docs/architecture/system-components.md` calls it the "first public-site baseline" but never flags it against the parent mandate, and that baseline has now held for five months while storing careers and investor submissions on an unreplicated volume. Needs three things, not one: a migration trigger, an owner, and a backup story. Owner: Dean.
- **There is no schema-evolution path on the volume that holds every submission.** Verified 2026-09-16: the API calls `Database.EnsureCreatedAsync()` at startup (`src/backend/FrostAura.Api/Program.cs:49`) and no `Migrations/` directory exists anywhere under `src/backend/`, although `Microsoft.EntityFrameworkCore.Design` is referenced by `FrostAura.Api`. `EnsureCreated` creates the schema only when the database is absent, so any change to `CareerSubmission` or `InvestorSubmission` either does nothing to an existing `frostaura-data` volume — leaving the API querying columns that are not there — or forces destroying the volume, which is every submission ever received. This is the operational half of the SQLite question and it is answered by the same decision: adopt EF migrations, or accept that the schema is frozen. Owner: unassigned.
- **No Tailwind, no shadcn/ui, no design system on the brand's front door.** Re-verified 2026-09-16: zero `@radix-ui/*` dependencies, no `tailwind.config`, no `components.json`; styling is one hand-rolled `src/web/src/styles.css`, the only stylesheet in `src/`. This is the surface where FrostAura's visual posture matters most. Adopt the mandated stack or record a waiver — the deviation has never been declared either way. Owner: Dean, parent-controlled.
- **The site runs an investor-capital funnel.** Verified 2026-09-16: `src/web/src/content/siteContent.ts` carries an investor hero ("A disciplined architecture for aligned capital…", CTA "Share your investment thesis") and a thesis block, and the API persists `CapitalRange`, `TimeHorizon`, `InvestorType`, `PreferredMode` and `Thesis` on `InvestorSubmission`. So the funnel is built, live and collecting, not aspirational copy. Whether soliciting outside capital at all is consistent with the parent's capital doctrine is not this scope's call — the parent-level half sits with root's founder-owned questions ([`../../../../memory/questions.md`](../../../../memory/questions.md)), and this scope records only that the mechanism exists and what it stores. Owner: unassigned.
- **What are the success metrics, and what would collect them?** A suggested set (organic visits, careers submissions, investor inbound conversion, Lighthouse score, Playwright pass rate) was never committed to, and **no analytics tooling exists in the repo** — re-verified 2026-09-16 by searching the frontend and `index.html` for any analytics or tag script. So even the suggestions are uncollectable today; the instrumentation decision has to come before the metric decision. Owner: Dean.
