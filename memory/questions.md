# Open questions

- **What deploys `frostaura.net`, from which image, and where does its data land?** The host serves this SPA and a live API, and nothing in this repo deploys it (see state). It still serves the 2026-09-16 build, which advertises killed products, and the image names it probably pulls were deleted on 2026-11-20, so it cannot update until CI republishes `technologies.fa.public-*` (deleted too by the last check, 2026-11-20) and someone repoints it. Until the deploying stack is found, nobody knows whether a push to `main` reaches production, whether submissions persist, or whether they are backed up. Two settings decide the funnels' fate and both default to failure (see gotchas): `ConnectionStrings__DefaultConnection` must point under `/app/data/` or submissions die with the container, and the SMTP keys must be set or both emails are skipped while the visitor is told it worked. Owner: `unassigned`.
- **SQLite instead of PostgreSQL, with no schema-evolution path and no backup.** Re-verified 2026-11-20: `Microsoft.EntityFrameworkCore.Sqlite` (10.0.15 since `22efe56`) in `FrostAura.Infrastructure` and the test project, no Npgsql anywhere; the API calls `Database.EnsureCreatedAsync()` at startup (`src/backend/FrostAura.Api/Program.cs:49`) and no `Migrations/` directory exists, although `FrostAura.Api` references `EntityFrameworkCore.Design`. `EnsureCreated` only builds a schema that is absent, so any change to `CareerSubmission` or `InvestorSubmission` either silently skips an existing `frostaura-data` volume or forces destroying it. `docs/architecture/system-components.md` calls SQLite the "first public-site baseline" and never flags it against the mandate. One decision answers both halves — migrate to Postgres with EF migrations, or declare a waiver and a frozen schema — and it was meant to land before the site deployed. The site is reachable in production (still so 2026-11-20), so the funnels may already be collecting into a schema that cannot evolve. Owner: Dean.
- **No Tailwind, no shadcn/ui, no design system on the brand's front door.** Re-verified 2026-11-20: no `@radix-ui/*` dependency, no `tailwind.config`, no `components.json`; `src/web/src/styles.css` is the only stylesheet. Adopt the mandated stack or record a waiver — the deviation has never been declared either way. Owner: Dean, parent-controlled.
- **Is `docs/references/FrostAura_Public_Landing_Page.html` a visual target, or only the content baseline?** An earlier context pass called it "the visual target the site is meant to match"; the project's own `docs/architecture/ui-ux.md` calls it the content and storytelling baseline and records the navigation-led SPA as a deliberate departure from its layout. Until this is ruled, comparing the site against it is not a defect check. A brand call. Owner: Dean, parent-controlled.
- **The site carries an investor-capital funnel.** Re-verified 2026-11-20: `siteContent.ts` has an investor hero (CTA "Share your investment thesis") and a "selective long-horizon partners" block welcoming "aligned capital", and `InvestorSubmission` stores capital range, horizon, investor type, preferred mode and thesis. It is **reachable in production**: on 2026-11-20 `frostaura.net/api/investors/submissions` answered `GET` with 405, a live POST-only route. Whether soliciting outside capital fits the parent capital doctrine is not this scope's call; this scope records only that the mechanism exists. Owner: Dean.
- **What are the success metrics, and what would collect them?** No metric set was ever committed, and no analytics or tag script exists in `src/web/src` or `index.html` (re-searched 2026-11-20). The instrumentation decision has to precede the metric decision. Owner: Dean.
